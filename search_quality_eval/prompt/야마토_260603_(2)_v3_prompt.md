## 3. 쿼리 파싱

### 3-1. 산지 추출

1. 쿼리에서 연도 표기 제거: `令和N年産`, `RN年産`, `YYYY年産`, `N年産`
2. `国産` 포함 여부 확인
3. 지역명 동치 매핑 적용 (§2-2)
4. 광역 산지 목록 전체 scan (§2-1)
5. `瀬戸内` 포함 여부 확인
6. 중복 제거 후 반환 (순서 유지)

**산지명 정규화:** 어미 `県/府/都/産` 제거

### 3-2. 가격 조건 추출

| 패턴 | 연산자 |
|------|--------|
| `N円以内`, `N円以下`, `N円まで`, `N円台`, `N円` | `<=` |
| `N円以上` | `>=` |
| `N円前後` | `~` |
| `高価格`, `高級` | `high` (val=null) |
| `安い`, `低単価`, `単価の低い`, `格安` | `low` (val=null) |

### 3-3. per-serving 가격 환산

쿼리에 `/食`, `一人前`, `人前`, `/人` 표현이 있으면 활성화:

```
per-100g 임계값 = 쿼리금액(円) × 100 ÷ 1식중량(g)
```

환산 결과를 `max_price_per_100g`로 사용한다.

### 3-4. 단위가격 예외 처리

쿼리에 `/kg`, `キロ`, `100g`, `円/kg`, `/100g` 표현이 있고  
tool_input에 `max_price_per_100g`, `max_price` 파라미터가 없으면  
**가격 채점 제외(UNKNOWN)** 처리.

## 4. 상품 평가 (상위 30위)

### 4-1. 기본값

검색이 반환한 카테고리 상품은 `relevance_score = 3` (기본 관련)으로 시작.

### 4-2. 원산지 게이트

쿼리에 산지 요구가 있을 때만 적용.

| 조건 | 결과 |
|------|------|
| 특정 광역 요구 + 상품 산지 일치 | `MATCH` → score=4, matched 추가 |
| 특정 광역 요구 + 상품이 다른 특정 광역 명시 | `MISMATCH` → score=0, violated 추가 |
| 특정 광역 요구 + 상품이 国産(generic)이거나 산지 불명 | `UNKNOWN` (채점 제외) |
| 国産(일본 내) 요구 + 광역 또는 国産 확인 가능 | `MATCH` → score=4, matched 추가 |
| 国産 요구 + 산지 불명 | `UNKNOWN` (채점 제외) |

> `国産`, `国`는 generic으로 처리 — 특정 광역 아님

### 4-3. 가격 게이트

우선순위: `max_price_per_100g` > `max_price` > 쿼리 단순값

| 파라미터 | 판정 |
|----------|------|
| `max_price_per_100g` 있음, 가격 없음 | UNKNOWN (price_unknown=true) |
| `max_price_per_100g` 있음, 중량 없음 | UNKNOWN (100g당 계산 불가) |
| `max_price_per_100g` 있음, p100 > 임계값 | score=0, violated |
| `max_price_per_100g` 있음, p100 ≤ 임계값 | matched |
| `max_price` 있음, 가격 > 상한 | score=0, violated |
| `max_price` 있음, 가격 ≤ 상한 | matched |
| 쿼리 `<=` 가격, 실제가 초과 | score=0, violated |
| 쿼리 `>=` 가격, 실제가 미달 | score=0, violated |

**100g당 단가 계산:**
```
p100 = selling_price × 100 ÷ weight_g
```

**상품명 중량 파싱:**  
패턴: `숫자 + (kg|ｋｇ|キロ|kｇ|g|ｇ|グラム|gr)`  
- `kg` 계열 → ×1000 환산  
- 복수 매칭 시 가장 큰 값 선택

### 4-4. relevance 레이블

| score | label |
|-------|-------|
| ≥ 3 | 적합 |
| 2 | 애매 |
| 0 | 유해 |

## 5. 필터 변환 정합성 평가

tool_input JSON에 쿼리 조건이 반영되었는지 검사 → `PASS / PARTIAL / FAIL`

| 조건 | 판정 |
|------|------|
| 쿼리 산지 없음 + 쿼리 가격 없음 | PASS |
| 산지·가격 모두 반영 | PASS |
| 일부 누락 | PARTIAL |
| 전체 누락 | FAIL |

**산지 반영 확인:** tool_input JSON 문자열에 정규화 산지명 또는 원문 또는 `国産` 포함  
**가격 반영 확인:** JSON 문자열에 `price` 키(대소문자 무관) 포함

## 6. 0건 케이스 분류

`product_count == 0` 이면 아래 로직으로 분류.

```
tools_used 배열이 비어 있지 않다
  → "검색 결과 없음"  (source: json.tools_used)

tools_used 배열이 비어 있다
  → answer_text에 [NORESULT_PATTERNS] 포함 AND [ASKBACK_PATTERNS] 미포함
       → "검색 결과 없음"  (source: answer_text_fallback)
  → 그 외
       → "역질문/상품 미반환"  (source: answer_text_fallback)
```

**NORESULT_PATTERNS:**  
`見つかりません 見つかりませんでした 該当する商品 該当商品 商品がありません 現在ありません 取り扱いがありません 検索結果がありません 在庫がありません ございません`

**ASKBACK_PATTERNS:**  
`どのような ご希望 教えてください お聞かせ 用途 条件 もう少し 具体的 お探しでしょうか`

## 7. 대안유도(대안 추천 위반) 탐지

"검색 결과 없음" 케이스에만 적용. 역질문/상품 미반환은 제외.

**위반 패턴 (ALT_PATTERNS):**  
`代わりに かわりに いかがでしょうか いかがですか おすすめいたします おすすめします お勧めします をご提案します はどうでしょう 代替商品をご提案 別の商品をおすすめ こちらもおすすめ もおすすめです`

**위반 예외 (ALT_NEG) — 이것이 있으면 거절 안내이므로 위반 아님:**  
`できません 特定できません 不明 対応しておりません 機能はございません お答えすることができません`

## 8. 100점 판정 로직

### 8-1. score100 계산

```
score100 = 100
  - 필터 FAIL:    -30
  - 필터 PARTIAL: -12
  - noise_ratio × 40  (noise_ratio = 위반상품수 / 평가상품수, max 1.0 clamp)
  - top3에 위반 상품 있음: -10
score100 = max(0, round(score100))
```

### 8-2. verdict 결정

| 조건 | verdict | final_judgement | llm_initial |
|------|---------|-----------------|-------------|
| score ≥ 90 AND top3 위반 없음 | Hard Pass | Hard Pass | Pass |
| score ≥ 70 | Conditional Pass | Conditional Pass | Warning |
| score < 70 | Fail | Fail | Fail |

### 8-3. 추가 플래그

| 항목 | 조건 |
|------|------|
| `is_outlier` | top3 평균 score < 0.5 (4점 만점 기준) |
| `human_review` | llm이 Warning/Fail OR is_outlier |
| `test_priority` | is_outlier+human_review → 1 / is_outlier만 → 3 / 이슈 있음 → 4 |

## 9. Phoenix 검증 (Warning/Fail 케이스만)

| 체크 항목 | OK 조건 |
|-----------|---------|
| `mapping_ok` | trace_id 존재 |
| `tool_call_ok` | tools_used 비어 있지 않음 |
| `params_ok` | filter_eval == PASS |
| `count_ok` | \|total_count - product_count\| ≤ max(5, product_count×0.5) |
| `retrieval_ok` | noise_ratio < 0.1 |
| `grounding_ok` | 항상 OK |
| `context_ok` | null |

**params_ok 매핑:** PASS→OK / PARTIAL→PARTIAL / FAIL→FAIL  
**retrieval_ok 매핑:** <0.1→OK / ≤0.3→PARTIAL / >0.3→FAIL

**phoenix_judgement 결정:**
```
FAIL 키 존재 (params_ok, retrieval_ok, grounding_ok 중 하나) → Fail
PARTIAL 값 존재 → Warning
그 외 → Pass
```

## 10. Relevance 지표 계산

```
c_avg = Σ(relevance_score) / (4 × n)   # 0~1 범위
rel   = 0.5 + c_avg×0.3 + (1-noise_ratio)×0.2
Acc   = min(1.0, score100/100 + 0.05)
Comp  = 0.8  (고정)
Score = score100 / 100
```
