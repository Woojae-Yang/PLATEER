상품 판정 라벨은 반드시 아래 3가지만 사용합니다.

- 적합
- 부분 적합
- 부적합

GELATTO KR/JP 공통 리포트에서는 `유해`라는 표현을 사용하지 않습니다.

## 응답 언어 정책

GELATTO KR/JP 공통 데이터셋에서는 한국어, 일본어, 영어 쿼리가 섞일 수 있습니다.
평가 시 아래 언어 정책을 적용합니다.

- 한국어 쿼리 → 한국어 답변을 기대합니다.
- 일본어 쿼리 → 일본어 답변을 기대합니다.
- 영어 쿼리 → 영어 또는 데이터셋 기본 언어의 답변을 허용하되, 상품명/브랜드명은 원문을 유지합니다.
- 멀티턴 대화에서는 직전 사용자 발화의 주 언어를 우선합니다.
- 사용자가 특정 언어로 답변을 요청한 경우 해당 언어 요청을 최우선으로 반영합니다.
- 쿼리 언어와 답변 언어가 불일치해 사용자 이해를 방해하면 답변 품질 또는 완성도에서 감점합니다.
- 상품명, 브랜드명, 카테고리명, 원문 description은 필요한 경우 원문 언어를 보존할 수 있습니다.

일본어 입력 예시:

```text
ユーザー: カーディガンをおすすめして
기대 답변 언어: 일본어
상품군 매칭: カーディガン, cardigan, 가디건, 가디간을 같은 상품군으로 취급
```

유의사항

- 입력 값의 text_keywords, vector_query, category_path는 없을 수 있으므로 감안해서 평가하세요.
- 검색 결과 파일의 모든 데이터를 보고 평가하세요.
- Claude가 직접 평가를 수행합니다. Anthropic API(v1/messages 등)를 직접 호출하지 마세요.
- 근거 결과를 포함한 HTML 시각화 리포트를 생성합니다.
- 원본 프롬프트 파일은 수정하지 않습니다.
- JSON 상품 목록 뷰어는 HTML 리포트 내 접힘 영역이 아니라 새 창(window.open)으로 여는 버튼으로 제공합니다.
- 각 상품별 description, exposure_reason, relevance_label, relevance_score를 HTML 리포트와 JSON Viewer에 표시합니다.
- CSV의 product_count가 0인 경우, 품질 평가 결과서에서 단순히 `결과 없음`으로 묶지 말고 `역질문/상품 미반환`과 `검색 결과 없음`을 구별해 표시합니다.
- 보조 JSON 파일이 제공된 경우, CSV row와 JSON record를 매칭하여 `tools_used`를 읽고 product_count = 0 분류에 우선 반영합니다.
- 가격 표기는 상품 JSON의 `currency` 값을 우선합니다. `currency = "KRW"`이면 `₩12,000` 또는 `12,000원` 형식으로 표시하고, `currency = "JPY"`이면 `¥12,000` 형식으로 표시합니다. KRW 상품을 엔화로, JPY 상품을 원화로 표기하지 마세요.
- GELATTO KR/JP 공통 패션 데이터는 미즈노 스포츠 상품군 기준으로 평가하지 않습니다. 의류, 가방, 신발, 액세서리, 룸웨어, 파자마 등 패션 커머스 상품군 기준으로 relevance_score를 산정하세요.
- 상품 판정 라벨은 `적합`, `부분 적합`, `부적합`을 사용합니다. `유해`라는 표현은 사용하지 않습니다.

## 평가 기준

기본 평가 순서와 점수 공식은 v1.7 구조를 유지하되, 상품군 판정과 relevance_score 산정은 GELATTO KR/JP 공통 패션 기준으로 재정의합니다.

- Step 0. 상위 결과 reasoning
- Step 1. 쿼리 세그먼트 태깅
- Step 2. 전체 상품 relevance_score 부여
- Step 2-K. 상위 3개 Top-K 집중 검사
- Step 3. A~F 항목 평가
- Step 3-M. 멀티턴 Ctx 점수 산출
- Step 4. 완전성 Comp 계산
- Step 4-M. 멀티턴 컨셉 드리프트 감지
- Step 5. 이슈 유형 자동 분류
- Step 6. is_judge_unstable 판정
- Step 7. Score 계산 및 최종 판정
- Step 8. 테스트 우선순위 분류
- Step 9. 31~100위 하위 검색 결과 이상치 검증

싱글턴 Score:

```text
Score = Rel × 0.35 + Pers × 0.15 + Acc × 0.30 + Comp × 0.20
```

멀티턴 Score:

```text
Score = Rel × 0.30 + Pers × 0.10 + Acc × 0.25 + Ctx_final × 0.20 + Comp × 0.15
```

Turn 1은 Ctx_final이 null이므로 싱글턴 공식을 적용합니다.

### 4. 상품명과 한국어/일본어/영어 쿼리 간 교차 매칭

GELATTO 상품명은 영어, 한국어, 일본어가 섞여 있을 수 있으므로 언어가 다르다는 이유만으로 부적합 처리하지 않습니다.

- `가디간 추천해줘` ↔ `Cassie Cardigan`, `Cashmere beaded cardigan`은 상품군 적합으로 봅니다.
- `퍼퍼 자켓` ↔ `puffer jacket`, `puff jacket`, `down jacket`, `자켓`, `점퍼`는 상품군 적합으로 봅니다.
- `캐쥬얼 팬츠` ↔ `denim pants`, `wide pants`, `slacks`, `jeans`는 상품군 적합으로 봅니다.
- `스니커 추천` ↔ `sneaker`, `sneakers`, `shoes`, `スニーカー`는 상품군 적합으로 봅니다.
- `파자마 추천` ↔ `pajama`, `pyjama`, `パジャマ`, `sleepwear`, `loungewear`는 상품군 적합으로 봅니다.
- `룸웨어 추천` ↔ `loungewear`, `homewear`, `ホームウェア`, `pajama set`은 상품군 적합으로 봅니다.
- `슬리퍼 추천` ↔ `room shoes`, `ルームシューズ`, `slippers`, `sandal`은 상품군 적합으로 봅니다.
- 브랜드명이 다르거나 category_path가 비어 있어도 상품명/답변/키워드가 상품군을 충족하면 relevance_score를 낮게 고정하지 않습니다.

### 5. GELATTO relevance_score 재정의

상품별 relevance_score는 0~4점으로 부여하되, 아래 기준을 사용합니다.

| score | label | 기준 |
| --- | --- | --- |
| 4 | 적합 | 쿼리 핵심 상품군과 주요 조건이 모두 맞고, Top-K에 노출해도 문제가 없는 상품 |
| 3 | 적합 | 핵심 상품군이 명확히 맞고, 색상/가격/스타일 등 일부 부가 조건이 없거나 약하지만 추천 가능한 상품 |
| 2 | 부분 적합 | 넓은 카테고리는 맞지만 세부 상품군이나 스타일이 다소 어긋남 |
| 1 | 부적합 | 같은 패션 카테고리 안에 있을 수는 있으나 쿼리 핵심 상품군과 직접성이 낮음 |
| 0 | 부적합 | 다른 대분류 상품, 명백한 오검색, 상품 정보 오류, 검색 의도와 무관한 결과 |

중요 규칙:

- KPI의 `상품 적합 비율`은 `relevance_score >= 3`인 상품을 적합으로 집계합니다.
- `부분 적합`은 적합 비율에는 포함하지 않지만, `유해`로 표기하지 않습니다.
- 기존 미즈노 스포츠 기준의 `유해` 라벨은 GELATTO 평가에서 사용하지 않습니다.
- 액세서리/관리용품을 무조건 노이즈로 보지 않습니다. 쿼리가 `머플러`, `스카프`, `버킷햇`, `벨트`, `쥬얼리`, `양말`, `헤어밴드`이면 액세서리가 정상 상품군입니다.
- 쿼리가 `파자마`, `룸웨어`, `잠옷`, `홈웨어`이면 룸웨어/파자마 상품군이 정상 상품군입니다.
- `category_path`가 없거나 비어 있어도 상품명, 브랜드명, answer_text, keywords, CSV의 기대 조건을 함께 보고 판단합니다.

### 6. GELATTO 점수 산정 우선순위

relevance_score 산정 시 아래 순서로 판단합니다.

1. 쿼리의 핵심 상품군 추출
2. 동의어 사전으로 KR/EN/JP 상품명 교차 매칭
3. CSV의 카테고리, 세부유형, 테스트관점, 특징과 비교
4. 상품명, brand_name, category_path, description, answer_text 내 상품 설명 비교
5. 색상, 가격, 사이즈, 소재, 스타일 등 부가 조건 반영
6. Top-K 3개는 핵심 상품군 일치 여부를 특히 강하게 확인

## product_count = 0 세부 분류 규칙

CSV의 `product_count`가 0인 경우, 반드시 아래 두 유형 중 하나로 분류합니다.

### 0. JSON tools_used 우선 판정 규칙

보조 JSON 파일이 함께 제공된 경우, CSV의 각 row와 JSON record를 먼저 매칭합니다.

매칭 키 우선순위:

```text
1. session_id
2. chat_request_id 또는 trace_id가 CSV에 있는 경우 해당 ID
3. user_query와 CSV 검색 쿼리의 완전 일치
4. 위 기준으로 매칭되지 않으면 기존 answer_text 기반 fallback 규칙 사용
```

매칭된 JSON record에 `tools_used`가 있으면, product_count = 0 분류에서 answer_text보다 `tools_used`를 우선합니다.

최우선 판정:

```text
CSV product_count = 0 AND JSON tools_used = ["search_products"]
→ 검색 결과 없음

CSV product_count = 0 AND JSON tools_used = []
→ 역질문/상품 미반환
```

의미:

- `tools_used = ["search_products"]`
  - 검색 도구를 실제 호출했으나 상품이 반환되지 않은 케이스입니다.
  - 따라서 사용자의 조건에 맞는 검색 상품이 없다고 보고 `검색 결과 없음`으로 분류합니다.
- `tools_used = []`
  - 검색 도구가 호출되지 않았고, LLM이 조건 확인 또는 안내 응답만 한 케이스입니다.
  - 따라서 상품 검색까지 가지 않은 `역질문/상품 미반환`으로 분류합니다.

예외 및 fallback:

```text
1. JSON 매칭 성공 + tools_used 존재 → tools_used 판정이 최우선
2. JSON 매칭 실패 → answer_text 기반 규칙 적용
3. tools_used가 null 또는 필드 없음 → answer_text 기반 규칙 적용
4. tools_used에 search_products 외 다른 도구가 포함된 경우 → tools_used, tool_name, products, total_count를 함께 보고 사람이 해석 가능한 reason을 남김
```

리포트에는 각 product_count = 0 row에 아래 필드를 표시하거나 내부 데이터에 포함합니다.

```json
{
  "zero_result_type": "역질문/상품 미반환 | 검색 결과 없음",
  "zero_result_source": "json.tools_used | answer_text_fallback",
  "tools_used": ["search_products"],
  "zero_result_reason": "tools_used=['search_products']이므로 검색은 실행됐으나 상품이 없어 검색 결과 없음으로 분류"
}
```

### 우선순위 규칙

동일 답변에 역질문 표현과 미검색 표현이 모두 있는 경우 아래 순서로 판정합니다.

```text
1. JSON tools_used = ["search_products"]이면 → 검색 결과 없음
2. JSON tools_used = []이면 → 역질문/상품 미반환
3. JSON 매칭 실패 또는 tools_used 없음 + 명시적 미검색/부재 표현이 있으면 → 검색 결과 없음
4. JSON 매칭 실패 또는 tools_used 없음 + 명시적 미검색 표현 없이 추가 조건 확인이 중심이면 → 역질문/상품 미반환
5. answer_text가 비어 있고 product_count = 0이면 → 검색 결과 없음
```

### 집계 규칙

`결과 없음`이라는 단일 집계/탭/배지는 사용하지 않습니다.

대신 아래 두 지표를 별도로 집계합니다.

```text
역질문/상품 미반환: N건
검색 결과 없음: N건
```

KPI 카드, 필터 탭, 총평에서 두 지표를 나란히 표시합니다.

예시:

```text
역질문/상품 미반환 38건
검색 결과 없음 81건
```

상품 가격은 `selling_price`를 우선 사용하고, 없으면 `original_price`를 사용합니다.

- `currency = "KRW"` 또는 한국어/KR 데이터셋이면 가격을 원화로 표시합니다.
  - 권장 형식: `₩149,000`
  - 대체 허용 형식: `149,000원`
  - 금지: KRW 상품을 `¥149,000`처럼 엔화로 표시
- `currency = "JPY"` 또는 일본어/JP 데이터셋이면 가격을 엔화로 표시합니다.
  - 권장 형식: `¥14,900`
- `currency` 값이 비어 있으면 파일명, 리포트 제목, 언어, 국가 코드(KR/JP)를 보고 추정하되, 추정 근거를 내부 notes에 남깁니다.
- HTML 상세 패널, 상위 상품 카드, 상품별 relevance_score 테이블, JSON Viewer 라이트 UI 모두 동일한 통화 표기 규칙을 적용합니다.

상품 0건이면 새 창 안에 zero_result_type에 따라 아래 empty state를 표시합니다.

```text
역질문/상품 미반환
검색 결과 없음
```

팝업이 차단되면 아래 alert를 표시합니다.

```javascript
alert('팝업이 차단되었습니다. 브라우저에서 팝업 허용 후 다시 열어주세요.');
```

## 용어 표기

상품 판정 용어는 아래처럼 통일합니다.

- good / 잘 맞음 / 관련 → 적합
- soso / 애매함 / 부분 관련 → 부분 적합
- miss / 안 맞음 / 노이즈 → 부적합
- GELATTO KR/JP 공통 패션 리포트에서는 상품 판정 라벨로 `유해`를 사용하지 않습니다.
- product_count = 0 + JSON tools_used = [] → 역질문/상품 미반환
- product_count = 0 + JSON tools_used = ["search_products"] → 검색 결과 없음
- JSON 매칭 실패 시 product_count = 0 + 역질문 응답 → 역질문/상품 미반환
- JSON 매칭 실패 시 product_count = 0 + 명시적 미검색 응답 → 검색 결과 없음

리포트 내 이모티콘은 사용하지 않습니다.
